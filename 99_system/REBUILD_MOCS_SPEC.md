# rebuild_mocs.py: Spec

## 1. Why this is a generator, not a repair tool

The wikilink crisis audit (2026-06-27) found `_MOCs/MOC_thinking.md` had 74
path-drift + 546 orphan links out of ~620 total. The MOC has not been a
working navigation index for the unknown number of sessions during which
content migrated under the 00..99 reorg. Repairing it one wikilink at a
time would mean:

- Trying to recover targets for 1,593 orphan links (many are gone for good
 : intentional archive cuts, deduplications, content that moved out of
  the vault entirely).
- Patching 421 path-drift links to their basename's new location, but
  inheriting whatever curation decisions the old MOC encoded: many of
  which no longer reflect what the vault contains.

The faster, more honest path: regenerate each MOC from **what the vault
actually contains right now**, grouped by tag. Files with the right
`#area/*` tag belong in the MOC. Files without it do not. The link list
becomes a function of current file state, not historical curation.

## 4. File-inclusion policy

Per-MOC scan walks the active vault (same EXCLUDE_PREFIXES as
`check_links.py`). For each `.md` file:

1. Parse YAML frontmatter. If absent or malformed -> skip (record to
   `UNROUTED.md`).
2. Read `tags:` field. Accept both list and inline forms; normalize to
   string set.
3. If file's tag set intersects MOC driver tags -> include in MOC.
4. **Exclusions per MOC:**
   - Files at `_MOCs/*.md` themselves -> excluded (MOCs don't link to MOCs
     except via MOC_Index.md, which is hand-maintained).
   - Files at `_handoff/*` -> excluded (operational, not content navigation).
   - Files at `99_system/*` -> excluded (infrastructure, listed in
     SYSTEM_DOC_MAP instead).
   - Files at `80_archive/*` for active MOCs -> excluded UNLESS
     `meta_status: active` is set (rare). Archived content goes in
     `MOC_historical.md` only.
5. Emit the include as `[[<vault-relative-path-without-extension>]]`.
   Honor R-WIKILINK-NOEXT: never write the `.md` suffix.

## 5. Conflict resolution

A file may match more than one MOC's driver tag set (e.g., a note tagged
both `#area/finance` and `#type/task`).

**Policy:** Multi-membership is allowed. A file appears in every MOC
whose driver tags it matches. NO single-MOC-pick decision is made by
the script. This is intentional: the old MOCs hand-curated mutual
exclusion, and that curation is what got lost. The current vault uses
tag-set membership as the navigation primitive: a finance task IS
both a finance note and a task, and should show up in both navigation
indexes. **Confirmed in OD-42 revision pass 2026-06-27.**

**Exception:** `MOC_historical.md` is exclusive: a file in there is
NOT also in other MOCs (archived files don't appear in active nav).
Implementation: any file with `meta_status: archived` OR path under
`80_archive/` is routed to MOC_historical only, regardless of its
`#area/*` or `#type/*` tags.

## 6. UNROUTED.md output

For each generator run, emit `_MOCs/UNROUTED.md` (overwrite). Contents:

- Files with no `tags:` field or empty `tags:`
- Files tagged only with `#area/*` that has no MOC mapping (`#area/home`,
  `#area/vehicle`, `#area/meta` per §3's deferred list)
- Files tagged only with `#type/*` tags that have no MOC driver
  (`#type/project`, `#type/routine`, `#type/log`) AND no `#area/*` tag
  to route them
- Files with malformed frontmatter
- Files where YAML parser raised an exception (with the exception text)

UNROUTED.md is grouped by the reason a file landed there: each section
shows file count. **When any group exceeds 20 files, that's the cue to
add a MOC for that bucket via a new OD** (one-line spec edit + script
re-run).

This list is the human triage queue: NOT silently dropped data.

```
$ python3 .claudian/scripts/rebuild_mocs.py --dry-run --moc MOC_finance

[rebuild_mocs] driver tags: #area/finance
[rebuild_mocs] scan: 870 active .md files
[rebuild_mocs] matched: 47 files
[rebuild_mocs] excluded: 12 (_handoff: 3, 99_system: 2, 80_archive: 7)
[rebuild_mocs] net include: 35 files

--- a/_MOCs/MOC_finance.md
+++ b/_MOCs/MOC_finance.md
@@ -1,12 +1,40 @@
[unified diff of current MOC body vs proposed new body]
```

`--apply` writes the file. `--moc <name>` limits to one MOC. Default
behavior with no args: print a one-line summary per MOC and exit
without writing.

broken count drops as expected.

## 9. What this script does NOT do

- Does not delete files. Ever. Emits link lists; that is all.
- Does not modify any file outside `_MOCs/` and `_MOCs/UNROUTED.md`.
- Does not call any model. No `ollama`, no `vault_agent.py`, no inference.
- Does not heuristically guess a file's MOC: if the tag isn't there,
  the file isn't included.
- Does not infer tags from filename or content. The tag is either in
  frontmatter or it isn't.
